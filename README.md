# AC Drip Monitor · ห้อง Server 5G

แจ้งเตือนเข้ากลุ่ม Telegram ทันทีเมื่อน้ำจากแอร์ (น้ำทิ้ง/น้ำแข็งละลาย) หยดหรือรั่วในห้อง Server ที่ปิดทึบ

## ทำไมต้องมี

ห้องนี้ชื้น และระบบวัดอุณหภูมิ/ความชื้นที่มีอยู่ไม่ครอบคลุมเรื่องน้ำรั่ว ถ้าน้ำจากแอร์หยดลงพื้นแล้วไหลไปถึง rack จะรู้ตัวก็ต่อเมื่อมีคนเข้าไปเห็น โปรเจกต์นี้ใช้บอร์ด ESP32 ราคาถูกกับแผ่นตรวจจับน้ำ 2 จุด ส่งข้อความเข้า Telegram โดยตรงจากบอร์ด (HTTPS) ไม่ต้องมี server กลาง

## ภาพรวมการออกแบบ

```
[แอร์] --หยด--> [ถาดตื้น + แผ่น①]            [แผ่น② จุดต่ำสุดของพื้น ข้าง rack]
                      |                                   |
                      +------------ สาย 3 เส้น ------------+
                                       |
                                       v
             [ESP32 DevKit V1 ในกล่อง]  <--  อแดปเตอร์ 5V  <--  เต้ารับ UPS
              LED GPIO2 กะพริบเมื่อพบน้ำ
                                       |
                                       |  WiFi 2.4 GHz (แนะนำ SSID/VLAN IoT แยก)
                                       v
                 api.telegram.org  (HTTPS, ตรวจ root CA)
                                       |
                                       v
                          กลุ่ม Telegram ของทีม
```

การทำงานของ firmware (`firmware/ac_drip_esp32/ac_drip_esp32.ino`):

- อ่านเซนเซอร์ทุก 5 วินาที: จ่ายไฟให้เซนเซอร์ผ่านขา GPIO → รอ 20 ms → อ่าน ADC 8 ครั้งเฉลี่ย → ตัดไฟ (จ่ายไฟเฉพาะตอนอ่าน ช่วยลดการกัดกร่อนของแผ่น)
- กันสัญญาณหลอก: ต้องอ่านได้ "เปียก" 2 ครั้งติดกันจึงถือว่าพบน้ำ และ "แห้ง" 2 ครั้งติดกันจึงถือว่ากลับปกติ
- ข้อความ Telegram:
  - 🟢 เปิดเครื่อง/รีบูต พร้อม IP, ความแรง WiFi (RSSI) และสาเหตุที่เริ่มใหม่
  - ⚠️ พบน้ำ: จุดไหน ค่า raw และเวลา
  - 🔁 ยังพบน้ำอยู่: ซ้ำทุก 1 ชั่วโมงจนกว่าจะแห้ง
  - ✅ กลับเป็นปกติ พร้อมระยะเวลาที่เปียก
  - 💓 ทุกวัน 08:30 (เวลาไทย) "ยังทำงานปกติ" พร้อมค่า raw ทั้งสองจุดและ RSSI — **ถ้าเช้าไหนไม่มีข้อความนี้ แปลว่าบอร์ดหรือเครือข่ายมีปัญหา**
- ส่งไม่สำเร็จ (เน็ตหลุด/Telegram ล่ม) ข้อความจะค้างในคิวและส่งซ้ำภายหลัง ไม่ทิ้งการแจ้งเตือน ⚠️ (คิวเก็บได้ 6 ข้อความ ถ้าเต็มจะทิ้งข้อความที่ไม่ใช่ ⚠️ ก่อน)
- WiFi หลุด: ต่อใหม่ทุก 30 วินาที ถ้าหลุดเกิน 10 นาทีจะรีบูตตัวเอง (คิวข้อความและสถานะเปียก/แห้งยังอยู่หลังรีบูต)
- มี watchdog (task watchdog, รีเซ็ตเมื่อค้าง): ถ้าโปรแกรมค้างเกิน 90 วินาที บอร์ดจะรีเซ็ตตัวเอง
- เวลา: ซิงก์ NTP (เขตเวลา ICT, UTC+7) ถ้า NTP ถูกบล็อกจะใช้เวลาจาก header ของ Telegram แทน ก่อนจะรู้เวลาจะไม่ส่ง 💓 08:30

|---|---|---|---|
| ① ใต้แอร์ | VCC | GPIO25 (D25) | จ่ายไฟเฉพาะตอนอ่าน |
| ① ใต้แอร์ | GND | GND | |
| ① ใต้แอร์ | AO | GPIO34 (D34) | ADC1 |
| ① ใต้แอร์ | DO | ไม่ต่อ | |

- แผ่นตรวจจับ (ตัวที่มีลายทองแดง) ต่อกับบอร์ด LM393 ด้วยสาย 2 เส้นที่ให้มา ขั้วไม่สำคัญ
- **ห้ามใช้ขา ADC2** (GPIO0, 2, 4, 12–15, 25–27) เป็นขาอ่าน AO เพราะใช้ไม่ได้ขณะเปิด WiFi — firmware ตรวจตอน compile ให้แล้ว
- LED สถานะ = LED บนบอร์ด (GPIO2) ไม่ต้องต่อเพิ่ม · ไม่มี buzzer
- rain module ให้ค่า **สูงเมื่อแห้ง (~4095) และต่ำเมื่อเปียก** จึงตั้ง `wetWhenLow = true`

### แผนอัปเกรดเซนเซอร์② (สายเปลือยขนาน)

ใช้สายเปลือย 2 เส้นวางขนานกัน (ห่างกันราว 5 มม.) แปะเทปตามแนวผนัง/โคน rack เพื่อจับน้ำได้เป็นแนวยาวแทนที่จะเป็นจุด:

- สาย A → GPIO26, สาย B → GPIO35, ตัวต้านทาน 100kΩ จาก GPIO35 ลง GND
- ถอดบอร์ด LM393 ของ② ออก
- ใน `SENSORS[]` แก้แถวของ② เป็น `wetWhenLow = false` แล้ว calibrate `threshold` ใหม่ (แห้ง ≈ 0, เปียกค่าจะสูงขึ้น)

firmware แยกค่าตั้งของแต่ละเซนเซอร์ไว้แล้ว (`name`, `pinPower`, `pinAdc`, `wetWhenLow`, `threshold`) จึงแก้แค่บรรทัดเดียว

## การแฟลช firmware

1. ติดตั้ง Arduino IDE 2.x
2. ติดตั้งไดรเวอร์ CH340 (Windows/macOS บางรุ่นต้องลงเอง; Linux มีในตัว) — ถ้าเสียบบอร์ดแล้วไม่เห็นพอร์ต COM ให้ลงไดรเวอร์นี้ และใช้สาย USB-C ที่ส่งข้อมูลได้ (ไม่ใช่สายชาร์จอย่างเดียว)
3. File → Preferences → Additional boards manager URLs ใส่
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
   แล้ว Tools → Board → Boards Manager ค้น "esp32" ติดตั้ง **esp32 by Espressif Systems** (ทดสอบ compile กับเวอร์ชัน 3.3.12)
4. สร้างบอท Telegram:
   - คุยกับ **@BotFather** → `/newbot` → ตั้งชื่อ → ได้ **bot token** (เก็บเป็นความลับ)
   - เพิ่มบอทเข้ากลุ่ม Telegram ของทีม แล้วพิมพ์ข้อความอะไรก็ได้ในกลุ่ม (เช่น `/start@ชื่อบอท`)
   - เปิด `https://api.telegram.org/bot<TOKEN>/getUpdates` ในเบราว์เซอร์ หา `"chat":{"id":-100...` → นั่นคือ **chat id** ของกลุ่ม (**กลุ่มจะขึ้นต้นด้วย `-` เสมอ** ต้องใส่เครื่องหมายลบด้วย)
   - ถ้า getUpdates ว่าง: ใน @BotFather `/setprivacy` → Disable แล้วส่งข้อความในกลุ่มใหม่
5. ในโฟลเดอร์ `firmware/ac_drip_esp32/` คัดลอก `secrets.example.h` เป็น `secrets.h` แล้วกรอก `WIFI_SSID`, `WIFI_PASS`, `BOT_TOKEN`, `CHAT_ID` (`secrets.h` ถูก gitignore ไว้ ห้าม commit)
6. เปิด `firmware/ac_drip_esp32/ac_drip_esp32.ino` ใน Arduino IDE
7. Tools → Board → **ESP32 Dev Module**, Tools → Port → เลือกพอร์ตของบอร์ด
8. กด Upload — ถ้าค้างที่ `Connecting....____` ให้ **กดปุ่ม BOOT ค้างไว้** จนเริ่มเขียน (เห็น `Writing at ...`) แล้วปล่อย
9. เปิด Serial Monitor ที่ **115200** baud ควรเห็นบรรทัด `[read ...]` ทุก 5 วินาที และกลุ่ม Telegram ได้ข้อความ 🟢 เริ่มทำงาน

ใช้ arduino-cli ก็ได้:

```
arduino-cli compile -b esp32:esp32:esp32 firmware/ac_drip_esp32
arduino-cli upload  -b esp32:esp32:esp32 -p /dev/ttyUSB0 firmware/ac_drip_esp32
```

## Calibration (ตั้งค่า threshold)

ค่า raw อยู่ในช่วง 0–4095 ค่าเริ่มต้นตั้ง `threshold = 2000` ไว้ แต่ควรวัดจริงทุกครั้งที่ติดตั้ง:

1. เปิด Serial Monitor (115200) ดูบรรทัด `[read ...] | ① ใต้แอร์ raw=xxxx ...`
2. จดค่า raw ตอน **แผ่นแห้ง** (มักใกล้ 4095)
3. หยดน้ำ 2–3 หยดบนแผ่น จดค่า raw ตอน **เปียก** (มักต่ำกว่า 1500 แล้วแต่ปริมาณน้ำ)
4. ตั้ง `threshold` = (แห้ง + เปียก) / 2 ของแต่ละเซนเซอร์ ใน `SENSORS[]` ที่หัวไฟล์ `.ino` แล้วอัปโหลดใหม่
5. เช็ดแผ่นให้แห้ง รอให้ขึ้น ✅

ค่าตั้งอื่นๆ (รอบอ่าน, เวลา heartbeat, ช่วงซ้ำเตือน ฯลฯ) อยู่ที่หัวไฟล์ `.ino` ส่วน `Configuration`

## การติดตั้งหน้างาน

ก่อนซื้อ/ติดตั้ง:

- **เช็ก WiFi 2.4 GHz ในห้อง** ด้วยมือถือ (แอปวัดสัญญาณ) ตรงจุดที่จะวางบอร์ด ต้องแรงกว่า **-75 dBm** (เช่น -60 ดี, -80 ไม่พอ) — ESP32 ใช้ 5 GHz ไม่ได้ และห้อง server มักบังสัญญาณ
- **ขอ SSID/VLAN สำหรับ IoT แยกจากเครือข่าย server** จากทีมเครือข่าย บอร์ดต้องออกเน็ตไป `api.telegram.org` พอร์ต 443 ได้ (NTP UDP 123 ถ้าได้จะดี แต่ไม่บังคับ)
- **เทน้ำเล็กน้อยใต้แอร์** ดูว่าน้ำไหลไปทางไหนและไปขังที่จุดใด จุดนั้นคือจุดวางแผ่น②

ติดตั้ง:

1. แผ่น① วางในถาดพลาสติกตื้นใต้จุดที่น้ำแอร์หยด (ถาดช่วยรวมน้ำให้โดนแผ่น)
2. แผ่น② วางราบกับพื้น ณ จุดต่ำสุดใกล้ rack ด้านลายทองแดงหงายขึ้น
3. บอร์ด ESP32 + บอร์ด LM393 ใส่กล่อง วางสูงจากพื้น (ไม่ให้โดนน้ำเอง) เดินสายเรียบร้อย ยึดด้วยเทป
4. เสียบอแดปเตอร์ 5V เข้าเต้ารับที่ต่อ **UPS**

### การทดสอบรับมอบ (ต้องผ่านทั้ง 3 ข้อ)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | หยดน้ำบนแผ่น① | ภายใน ~10–15 วินาที LED กะพริบ และกลุ่มได้ ⚠️ ระบุ "① ใต้แอร์" · เช็ดแห้งแล้วได้ ✅ |
| 2 | หยดน้ำบนแผ่น② | ได้ ⚠️ ระบุ "② พื้นจุดต่ำข้าง rack" · เช็ดแห้งแล้วได้ ✅ |
| 3 | ถอดปลั๊กบอร์ดแล้วเสียบใหม่ | ได้ 🟢 เริ่มทำงาน พร้อม IP และ RSSI |

จด RSSI จากข้อความ 🟢 ไว้เป็นค่าอ้างอิง

## บำรุงรักษาประจำเดือน

- ตรวจว่ายังได้ 💓 ทุกเช้า 08:30 (ถ้าขาดให้ตรวจไฟ/WiFi/บอร์ดทันที)
- ทดสอบหยดน้ำบนแผ่นทั้งสอง ต้องได้ ⚠️ และ ✅
- ดูแผ่นตรวจจับ: ถ้าลายทองแดงดำ/เป็นสนิม/มีคราบ ให้เช็ดทำความสะอาดหรือเปลี่ยนแผ่น (แผ่นละไม่กี่สิบบาท) แล้ว calibrate ใหม่
- เทน้ำที่ค้างในถาดของแผ่น① ทิ้ง ตรวจว่าแผ่นยังอยู่ตำแหน่งเดิม สายไม่หลุด
- ดู RSSI ในข้อความ 💓 ถ้าแย่ลงจนต่ำกว่า -80 dBm ให้ย้ายบอร์ดหรือแจ้งทีมเครือข่าย

## ข้อจำกัดที่รู้อยู่แล้ว

- **แผ่นตรวจจับรู้เฉพาะจุดที่วาง** ถ้าน้ำไหลไปทางอื่นจะไม่รู้ (แผนอัปเกรดสายเปลือยขนานช่วยให้จับเป็นแนวยาวขึ้น)
- ความชื้นสูงมาก/ไอน้ำเกาะแผ่นอาจทำให้ค่า raw ลดลง ต้อง calibrate ให้ threshold ห่างจากค่าตอนแห้งพอสมควร
- ไฟดับนานกว่าที่ UPS รับไหว หรือเครือข่าย/อินเทอร์เน็ตล่ม = ไม่มีการแจ้งเตือน (สังเกตได้จาก 💓 ที่หายไป) ข้อความที่ค้างในคิวหายถ้าไฟดับ (คิวอยู่รอดเฉพาะการรีบูตตัวเอง)
- ขณะกำลังส่งข้อความ (ปกติ 1–3 วินาที, แย่สุดราว 50 วินาทีเมื่อเครือข่ายมีปัญหา) การอ่านเซนเซอร์จะหยุดชั่วคราว
- ถ้า Telegram เปลี่ยนไปใช้ root CA ที่ไม่อยู่ใน `telegram_ca.h` การส่งจะล้มเหลว (Serial ขึ้น TLS error และ 💓 หายไป) ต้องเพิ่ม CA ใหม่แล้วแฟลชใหม่ — ดูคำอธิบายในไฟล์นั้น (root ที่ใช้อยู่ Go Daddy Root G2 หมดอายุปี 2037)
- ถ้าสาย AO หลุด ขาอ่านจะลอยและค่าอาจแกว่ง ยังไม่มีการตรวจจับสายหลุดอัตโนมัติ — ดูค่า raw ใน 💓 ประกอบ
- ถ้ากลุ่ม Telegram ถูกอัปเกรดเป็น supergroup (chat id เปลี่ยน) firmware จะใช้ id ใหม่ให้อัตโนมัติจนกว่าจะไฟดับ ให้แก้ `CHAT_ID` ใน `secrets.h` ตามที่ Serial แจ้ง
